场景 02 / 设备匹配

两种 Class，能选中同一张卡

node-a 有两张 A100，node-b 有两张 H100。管理员提供 gpu-any 和 gpu-a100：前者选任意 GPU，后者只选 A100。它们会同时匹配 node-a 的两张卡。

Node / node-a

这台机器提供本地设备。通常由 kubelet 注册；这里列出来是为了对照 Slice 的 nodeName。

# 教学示例：两个节点，两个可重叠的 DeviceClass。
# gpu-any 匹配四张卡；gpu-a100 只匹配 node-a 上的两张卡。
apiVersion: v1
kind: Node
metadata:
  name: node-a
下载所在 YAML 文件

4 + 2，为什么还是 4？

gpu-any 匹配四张卡，gpu-a100 匹配其中两张。两个集合重叠，所以集群物理 GPU 总数还是四张。按 Class 统计资源时，不能把它们直接加起来。

Slice 没有绑定 Class

ResourceSlice 不写 deviceClassName。Class 用 CEL 检查设备的 driver 和 attributes；一个设备能匹配多个 Class，一个 Class 也能覆盖多个节点、多个 Pool。Class 还可以带驱动配置，这页只看匹配。

规则由谁决定？

通常由管理员或安装驱动的 Helm chart 创建、更新 DeviceClass。修改 Class 改的是用户可选择的匹配条件；哪些设备被发现、发布，则由 driver 及其配置决定。不要把 Class 的存在本身当作租户授权。

两边都叫 gpu-0，会撞吗？

不会。设备身份是 (driver, pool, device)。这里两个节点的 Pool 分别叫 node-a 和 node-b，所以它们是两张不同的卡。
