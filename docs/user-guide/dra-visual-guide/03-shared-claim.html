场景 03 / 复用 Claim

两个 Pod，引用同一份分配

trainer-a 已经通过 shared-gpu 拿到 gpu-0。随后 trainer-b 也引用 shared-gpu。它复用已有分配，不会因为多一个 Pod 就再申请一张卡。

Node / node-a

这台机器提供本地设备。通常由 kubelet 注册；这里列出来是为了对照 Slice 的 nodeName。

# 教学示例：两个 Pod 引用同一 ResourceClaim，复用同一份分配结果。
# 这不表示驱动自动提供时间片或容量隔离；示意 trainer-a 分配后 trainer-b 复用。
apiVersion: v1
kind: Node
metadata:
  name: node-a
下载所在 YAML 文件

为什么第二个 Pod 不再扣一张？

设备分给了 Claim。两个 Pod 引用的是同一个 Claim，因此在这个独占整卡例子里，已占用设备仍然只有 gpu-0 一张。node-a 还有另一张 gpu-1。

两个 Pod 仍要能访问设备

本例的 gpu-0 只能在 node-a 使用，所以两个 Pod 都要满足这个节点约束。把 Claim 共享给另一个 Pod，不会改变设备的可访问范围。

这和下一页的 vGPU 共享有什么不同？

这里复用一份 allocation，没有给每个 Pod 单独申请算力和显存额度。真正的容量共享会创建两个独立 Claim，让调度器分别记账。驱动是否支持多 Pod 共同使用同一份分配，还要看具体实现。

本页只解释通用 DRA 关系

这个例子不代表 HAMi 已验证支持同一 Claim 的多 Pod 复用，也不保证时间片或显存隔离。HAMi 示例采用一个 Pod 对应一个独立 Claim。
