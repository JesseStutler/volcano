01
从这里开始

一个 Pod，申请一张 GPU

Pod 引用 Claim，Claim 选 Class，Class 的条件去匹配 Slice 里的设备。

↗02
设备匹配

两种 Class，能选中同一张卡

Class 定义选择条件。给同一张卡再加一个匹配的 Class，不会多出一份库存。

↗03
复用 Claim

两个 Pod，引用同一份分配

两次引用，一个 Claim，一份 allocation。

↗04
Pool 与节点

同一份库存，分两张表发布

Pool 用 (driver, pool.name) 识别；resourceSliceCount 统计同一代有几份 Slice。

↗05
Consumable capacity

卡还在用，容量还没用完

同一个 device 可以多次分配；每次分配都消耗它的容量。

↗06

用 HAMi，把一张卡分给两份推理

DRA 负责选择设备、分配容量；HAMi-core 在容器运行时执行资源限制。

↗07
Admission 转换

还写 nvidia.com/gpu，也能转成 Claim

旧字段是提交入口，调度时仍然使用 ResourceClaim。

页面怎么用？

每个场景有独立地址。先看图，再点资源卡片，对照旁边的 YAML。示例文件、SVG 和 PNG 都能下载。整个目录保存下来后，直接打开 index.html 就能离线阅读。

这些 YAML 能直接装出一套集群吗？

前五页使用教学驱动 gpu.example.com，用来解释 API。最后两页按 HAMi 的实际实现整理用户请求，但仍需要先安装驱动与运行时。只读示意单独放在 observations，不能拿来替代驱动发布库存。各场景独立，不要混合应用。

版本基线

Kubernetes 1.36；HAMi NVIDIA driver v0.1.1。对应源码链接放在每页末尾。页面和 API 示例已经校验，未在真实 GPU 集群执行。

自己部署

一条命令，把这份图解放到服务器上

在仓库根目录运行（需要 Docker）：

./docs/user-guide/dra-visual-guide/serve.sh

默认访问服务器的 8080 端口。也可以用 Python 本地预览，或者把整个目录复制到已有静态网站。
