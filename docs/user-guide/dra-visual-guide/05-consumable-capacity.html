场景 05 / Consumable capacity

卡还在用，容量还没用完

一张 40Gi GPU，算力额度按 100 计。两个推理服务各申请 30 份算力、12Gi 显存。它们使用两个独立 Claim，但可以被分到同一张卡。

三个字段分别管什么？

allowMultipleAllocations: true 允许多次分配；capacity 声明设备的总容量和请求规则；Claim 的 capacity.requests 写这次每个设备要消耗多少。这里 cores 的单位由教学驱动约定为百分比，Kubernetes 不会自行规定这个名字的物理含义。

分完两份，还剩多少？

假设 A 和 B 都选中 gpu-0，已分配为 60 / 100 算力、24 / 40Gi 显存。剩余 40 算力、16Gi 显存。第三份请求必须两个维度都够；下面可以改数字试一试。

Slice 的 value 会扣减吗？

不会，Slice 仍写总量 100 和 40Gi。分配消耗记录在 Claim 的 allocation 中，调度器结合当前分配状态判断余量。它统计的是已经分出去的额度，不是 GPU 此刻的监控利用率。

没写容量会怎样？

本例的 requestPolicy.default 是整卡容量。省略某个维度，会按该维度默认值请求，可能直接占满。count: 2 表示选两张设备，capacity.requests 则针对每张设备，不是两张设备合计。

运行条件

以 Kubernetes 1.36 为基线，DRAConsumableCapacity 已 beta 且默认启用；1.34–1.35 需要显式启用。还需要真正支持这些字段的调度器、驱动和运行时。本页是假想驱动教学例，不是安装清单。
