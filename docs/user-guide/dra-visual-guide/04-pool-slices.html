什么时候会拆？

最常见是设备条目太多，或 driver 按自己的库存结构拆分发布。Kubernetes 1.36 一份 Slice 最多放 128 个 device；使用 taints 或 consumesCounters 时上限降为 64。本例每份只有一张卡，是为了把关系画清楚，并非必须拆。

为什么两个 Slice 要写同样的 generation？

generation 表示这组库存的版本。这里两个 Slice 都属于 node-a Pool 的第 1 代，且都声明 resourceSliceCount: 2。新一代发布不完整时，调度器不能把一半新库存和一半旧库存拼起来当作完整 Pool。

MIG 还有一种拆法

启用动态 MIG 的 driver 可以把共享计数器与候选设备分别放进 Slice。Kubernetes 1.36 的 sharedCounters 和 devices 不能放在同一份 Slice。候选 MIG 配置也不能全当成能同时存在的物理 GPU。

Pool 为什么常常叫 node name？

本地 GPU 驱动通常由每个节点上的实例维护本机库存，所以用节点名作为 Pool 名很自然。同一个 driver 管理多台节点，就会出现多个 Pool。Pool 名本身不决定可访问节点，真正的字段是 nodeName、nodeSelector 或 allNodes。

放到 NVL72 怎么理解？

如果一个机架的 18 个计算托盘各自注册成一个 Kubernetes Node，且每个托盘有 4 张 GPU，本地 GPU driver 通常会发布 18 个 Pool，每个 Pool 4 张卡。NVLink 互联不会自动把它们变成一个 allNodes Pool；实际仍看驱动的发布方式。
