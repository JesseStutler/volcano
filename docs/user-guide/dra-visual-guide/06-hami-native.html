用 HAMi，把一张卡分给两份推理

假设 node-a 上有一张 24Gi GPU，HAMi driver 将它发布为 hami-gpu-0。两个服务分别申请 50% 算力和 10Gi 显存，各用一个 Claim。

只读示意，用来理解发布或分配后的字段；不要把它当作创建输入。driver 发布的设备库存。先看 driver、pool 和 nodeName，再看 devices。Pool 名不是一个独立对象的引用。

# 只读示意：根据 HAMi NVIDIA driver v0.1.1 和 HAMi-DRA chart 整理。假定实际显存24Gi；名称/属性简化。勿手工替代驱动发布。
apiVersion: resource.k8s.io/v1
kind: ResourceSlice
metadata:
  name: node-a-hami-gpu-example
spec:
  driver: hami-core-gpu.project-hami.io
  nodeName: node-a
  pool:
    name: node-a
    generation: 1
    resourceSliceCount: 1
  devices:
  - name: hami-gpu-0
    attributes:
      type:
        string: hami-gpu
    allowMultipleAllocations: true
    capacity:
      cores:
        value: '100'
        requestPolicy:
          default: '100'
          validRange:
            min: '0'
            max: '100'
            step: '1'
      memory:
        value: 24Gi
        requestPolicy:
          default: 24Gi
          validRange:
            min: 1Mi
            max: 24Gi
            step: 1Mi

先认这几个真实名字

driver 和默认 DeviceClass 都叫 hami-core-gpu.project-hami.io，device 形如 hami-gpu-0，Pool 通常用节点名。这里的库存示意根据 NVIDIA driver v0.1.1 整理，24Gi 是教学假设，实际显存由驱动探测。

50 是什么？

cores: 50 表示算力百分比，不是 50 个 CUDA core，也不是固定独占一半 SM 或保证一半吞吐。memory: 10Gi 是显存容量。该版本发布 cores 和 memory 两个容量维度，没有 capacity.count。

两个 Claim 能落在同一张卡吗？

可以，前提是调度时容量和其他约束都满足。图中假设两份都分到 hami-gpu-0：算力额度已经分完，显存还剩 4Gi。再来一个需要正数算力的 Claim，这张卡就满足不了，即使显存还有空余。

限制是怎么进容器的？

调度器把消耗量写入 Claim allocation。节点上的 DRA driver 读取 consumedCapacity，通过 CDI 挂入 HAMi-core，并设置显存、算力限制。运行 CUDA 时由 HAMi-core 执行限制；这属于软件共享，与 MIG 的硬件分区不同。

写 YAML 时别省掉一个维度

HAMi 的默认 cores 是 100，默认 memory 是全部显存。示例同时写两项，避免意外请求整卡。显存步长为 1Mi，算力步长为 1；请求规则可能向上取整，所以最终应看 allocation 的 consumedCapacity。

如何拿去试？

先按 HAMi-DRA 官方安装说明配置 NVIDIA 驱动、DRA driver、CDI 和 feature gate，再使用本页的用户 YAML。示例走默认调度器；如果切到 Volcano，先确认目标版本支持 consumable capacity。这里做了 API 校验，没有在真实 GPU 上验证运行。
