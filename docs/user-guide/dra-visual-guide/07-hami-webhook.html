场景 07 / Admission 转换

还写 nvidia.com/gpu，也能转成 Claim

已有应用习惯在 Pod limits 中写 GPU 数量、显存和算力。HAMi-DRA 的 webhook 可以把这类请求转成 DRA Claim，再给 Pod 补上引用。

Pod / inference-compatible

使用者。spec.resourceClaims 关联 Claim，容器的 resources.claims 通过本地别名选择它。

# 用户提交：需 HAMi-DRA admission webhook。gpumem 单位为 MiB，10240 MiB = 10 GiB。
apiVersion: v1
kind: Pod
metadata:
  name: inference-compatible
  namespace: default
spec:
  restartPolicy: Never
  containers:
  - name: app
    image: nvidia/cuda:13.0.1-base-ubi9
    command:
    - sh
    - -c
    - sleep 3600
    resources:
      limits:
        nvidia.com/gpu: 1
        nvidia.com/gpucores: 50
        nvidia.com/gpumem: 10240
下载所在 YAML 文件

最容易写错的是显存单位

nvidia.com/gpumem: 10240 的单位是 MiB，转换后才是 memory: 10Gi。这里不要直接把 gpumem 写成 10Gi。nvidia.com/gpu: 1 对应 exactly.count: 1，gpucores: 50 对应 capacity.requests.cores: 50。

webhook 改了哪些地方？

默认模式会创建 ResourceClaim，给 Pod 增加 spec.resourceClaims 和容器的 resources.claims，并移除已经转换的扩展资源字段。右侧结果示意简化了生成名称和别名，重点看字段对应关系；不是集群抓取结果。

这不需要用户手写第二份 Claim

用户提交的是转换前的 Pod。转换后的对象由 webhook 管理，不要再把示意结果 apply 一次。当前 chart 也支持 ResourceClaimTemplate 模式，本页只展示默认的直接 Claim 模式。

什么时候选这个入口？

迁移已有应用、不想立刻改提交模板时比较方便。新应用直接写原生 Claim，字段含义更清楚。两种入口最终仍依赖 DRA 分配与 HAMi-core 限制；安装 webhook 还要按官方说明配置证书等依赖。
